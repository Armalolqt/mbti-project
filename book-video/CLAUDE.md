# 拆书视频工作室 · Claude Code 工作规范

这个项目做的是**像素游戏风的拆书视频**：一本书拆成「一个核心比喻 + 四关」，横屏 16:9，单期 5–6 分钟，发抖音。
每期素材放在 `episodes/<期号>-<书名拼音>/`。动手前先读这份文件，再读当期的 `script.md` 和 `storyboard.json`。

---

## 0. 你（Claude Code）在这个项目里的分工

| 环节 | 谁做 | 产物 |
|---|---|---|

| 配音 + 字幕时间轴 | **你** | `audio/voice.mp3`、`audio/timings.json` |
| UI 组件、动效、合成、导出 | **你** | `out/<期号>.mp4` |

插画还没到位的场景，先用占位图（深蓝底 + 场景ID + 描述文字）把整片跑通，图到了直接替换同名文件。

## 1. 内容公式（参考样片：「一只索尔」拆《滚雪球》，5分27秒）

时间占比按 5.5 分钟算：

| 段落 | 占比 | 要做到什么 |
|---|---|---|
| 钩子 | ~6% | 一个比喻或一件热点，然后讲为什么大多数人做不到，最后才亮书名 |
| 背书 + 叠甲 | ~6% | 一句话交代这本书为什么可信，再说清「今天不讲什么」，同时把受众范围扩大 |
| 总纲 | ~3% | 一句话把四关串起来（「书名就是说明书」这一类） |
| 第一～四关 | 各 ~15% | **每关固定四步：原则 → 书里的故事或研究 → 一个狠数字或道具 → 「放到你身上」**，关尾一句金句 |
| 行动卡 | ~6% | 「送你三张卡，今晚就能用」，每张一句话 |
| 诚实补丁 | ~2% | 主动交代这本书或这套方法的边界，这是可信度的来源 |
| 回扣 + 结尾 | ~8% | 回到开头的比喻收尾；评论区问题要低门槛（「回一个字就行」）；最后一句「我们下一本书见」 |

## 2. 文案规则

- 一句字幕 = 一行，**每屏不超过 18 个字**。`text` 超过 18 字时，你在合成时按标点（，；：）拆成两屏，按字数比例分配时长；配音不断，高亮词跟着它所在的那一屏走。语速约每秒 4.3 字。
- 全程第二人称。每个概念都马上翻译成观众的日常场景。
- 一期只用**一个**核心比喻，所有关卡标题都是它的变体。
- 【】标记的是金色高亮关键词，每句最多两个。
- 关尾金句标 ★：字号放大 1.25 倍，停顿 0.6 秒。
- 书里的概念要准。拿不准的事实写进 `script.md` 的「事实核对」表，不要编页码和原文引语。
- 不点名引用真人的原话。借势热点时只转述大意。

## 3. 视觉系统

**画面**：16-bit 像素风，电影感打光。主色是暖台灯琥珀 `#E8B04A`，底色深夜海军蓝 `#1B2340`，情绪色可以每期换（《亲密关系》用玫瑰粉 `#E58FA0`）。人物 Q 版比例，同一期里同一个角色外观不能变。

**常驻层**（全片一直在）：
1. **顶部导航条**：高 56px，四个 tab 平分宽度，当前关卡 tab 背景提亮、文字变白，其他 tab 文字 50% 透明。开场和结尾段四个都不高亮。数据来自 `storyboard.json` 的 `nav_tabs`，当前项取 `lines[].nav_active`。
2. **右上角水印**：`{{频道名}} · 书名`，字号 22px，40% 白。频道名：**风的攻略**（例：`风的攻略 · 亲密关系`）。
3. **底部字幕**：居中，距底 70px，像素描边粗体（比如「Zpix」或「方正像素」这类像素字体，没有就用粗黑体加 3px 黑描边），字号 46px；高亮词用 `#E8B04A`。

**UI 组件库**（放在 `components/`，每期复用，做一次就要做成参数化的）：
| 组件 | 参数 | 动效 |
|---|---|---|
| `ChapterCard` 关卡标题卡 | 关号、标题 | 从上方落下，带灰尘粒子，停 1.5 秒 |
| `ItemCard` 装备卡 | 名称、稀有度、属性列表 | 弹出 + 旋转光晕，属性逐行出现 |
| `SkillCard` 技能卡 | 序号、名称、星级、卡面图 | 宝箱里飞出，翻转放大 |
| `ChoiceBox` RPG 选项框 | 选项数组、默认光标 | 光标在选项间犹豫，最后停在某项 |
| `Achievement` 成就弹窗 | 类型（结局或成就）、文字 | 右上滑入，金色描边闪一下 |
| `Counter` 数字滚动 | 起止值、单位 | 0.8 秒滚动，结尾放大一下 |
| `Gauge` 尺子或刻度条 | 刻度值、现实值、颜色阈值 | 柱子升降，跨过阈值时变色 |
| `Matrix2x2` 四格矩阵 | 四格文字、高亮格 | 依次点亮 |
| `Scale` 天平 | 左右砝码数 | 砝码逐个落下，最后平衡 |
| `LoopArrows` 循环图 | 节点文字 | 循环转动，越转越快 |
| `LineChart` 像素折线 | 数据点、标注 | 从左往右画出来 |
| `CommentBtns` 评论区引导 | 两个选项 | 呼吸闪烁 |

**镜头**：每个画面都要动，可以缓推、平移，或者让元素弹出，不要有超过 1 秒的完全静止。画面约 4–6 秒换一次，字幕约 3 秒换一次。转场用 0.3 秒硬切或者像素溶解，不要用花哨的转场。

## 4. 制作流水线

视频框架用本机已经装好的 **HyperFrames**（用户主目录下有 `.hyperframes`）。开工前先读它的文档或 skill，确认合成文件的写法；如果 HyperFrames 搞不定，可以换 Remotion，但要先跟我说。

1. **读分镜**：`storyboard.json`，`lines[]` 是逐句字幕，`scenes{}` 是场景定义。
2. **配音**：默认用 `edge-tts`（`pip install edge-tts`），音色 `zh-CN-YunxiNeural`，语速 `+8%`。用 `tts_text` 字段，每句单独合成，然后拼接，句间留 0.35 秒，★ 句后留 0.6 秒。用每句的实际音频时长覆盖 `est_start` 和 `est_duration`，写入 `audio/timings.json`。以后换成别的 TTS 或真人配音，只换这一步。
3. **出图清单**：`kind` 是 `image` 或 `mix` 的场景，按 `image-prompts.md` 出图。描述是中文的，生成英文提示词时一定带上统一风格前缀。缺图就用占位图。
4. **合成**：背景图 → 镜头运动（`motion` 字段）→ UI 组件 → 常驻层（导航条、水印、字幕）。`kind: ui` 的场景全部用代码画，画在深蓝底的像素房间背景上。
5. **音乐**：`assets/bgm/` 里如果有文件，混在 -22dB，配音出现时自动压低（ducking）；没有就留空。
6. **导出**：1920×1080，30fps，H.264（`-preset veryfast -crf 20`），AAC 192k → `out/<期号>.mp4`。另外导出一份 `out/<期号>_preview.mp4`，720p，用来快速审片。

## 6. storyboard.json 字段

- `nav_tabs`：导航条四个 tab 的文字
- `scenes.<ID>.kind`：`image`（只用插画）、`mix`（插画加代码叠加）、`ui`（全部代码画）
- `scenes.<ID>.description`：画面内容。mix 场景里写在括号「（代码：…）」中的部分由你实现
- `lines[]`：`id`、`text`（字幕）、`tts_text`（配音用）、`highlight`（金色词数组）、`is_punchline`（★）、`scene`、`motion`（镜头和动效提示）、`nav_active`（0 表示都不高亮）、`est_start`、`est_duration`
- 同一场景连续多句时，画面不切，只做 `motion` 里写的变化。

## 8. 不要做的事

- 不要改文案措辞。觉得哪句不好，写在报告里建议，由我决定。
- 不要把真人照片、书籍出版社的封面原图放进画面。书在画面里统一画成像素风的「一本厚书」，书名用代码渲染成文字。
- 不要换掉统一风格去追求「更好看」的单帧。每期之间的一致性比单帧好看重要。
